# Demo / Pitch

## Short pitch structure

### 1. Problem
One concrete sentence: what problem exists and for whom?

### 2. Baseline
How does it work without our solution, and where is the inefficiency?

### 3. Solution
What does our adaptive/AI system do?

### 4. Where is the AI / optimization?
What does the system observe?
What does it choose/change?
What feedback does it receive?
How does it improve?

### 5. Metrics
Show 1–3 numbers directly tied to the official case.

### 6. Evidence
Show Baseline vs Optimized under comparable conditions.

### 7. Live demo
Minimal flow:
1. input/state;
2. baseline;
3. optimization;
4. changed strategy/result;
5. metrics;
6. improvement.

### 8. Codex usage
If required by the organizers, explain briefly how Codex was used in the team workflow.

### 9. Scale / next step
Explain why the architecture can generalize to a larger or adjacent problem.

## Demo safety
Prepare:
- stable scenario;
- screenshots;
- backup video if allowed;
- README run steps;
- known-good commit/tag;
- offline copy of key evidence.

## Rule
Never say "AI made it better" without a measurable result.
